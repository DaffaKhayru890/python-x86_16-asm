# `tests`

```sh
sh tools/run_tests.sh
```

The harness builds the image, copies it to `build/tpp.com` (an eight-character
name, because DOS without long-filename support cannot open a thirteen-character
command), runs each case in DOSBox-X with its output redirected to a file, and
compares that file **byte for byte** with `expected/<name>.txt` — banner line,
CRLF endings and caret positions included. It then reads the exit code back with a
ladder of `if errorlevel` tests, since the built-in shell of DOSBox has no
`%ERRORLEVEL%` variable to echo.

Set `DOSBOX_X` if the emulator is not on `PATH` and not at the usual Windows
location. Exit status is nonzero if anything differs.

## `valid/` — must run, exit code 0

| Case | Source | Output after the banner |
| --- | --- | --- |
| `hello` | one statement | `Hello, World!` |
| `multi` | three statements | `One`, `Two`, `Three` in order |
| `empty` | `print("")` | one empty line |
| `special` | `$`, `\"`, mixed-case keyword | `Price: $100`, `Quoted: "Hi"`, `Mixed Case ok` |
| `blanks` | leading and interior blank lines, tab and space indentation, trailing spaces | `after blanks`, `tabbed` |
| `zero` | an empty file | nothing: the stream is a single HALT cell |

## `invalid/` — must be refused

| Case | Source | Report | Exit |
| --- | --- | --- | --- |
| `noparen` | `print("no closing paren"` | `missing ) after the string`, line 1 column 7 | 2 |
| `noopen` | `print "no opening paren")` | `missing ( after print`, line 1 column 7 | 2 |
| `noquote` | `print("never closed` and a line break | `string literal is not closed`, line 1 column 7 | 2 |
| `noarg` | `print()` | `print needs a string literal`, line 1 column 7 | 2 |
| `badword` | `puts("not the keyword")` | `expected the print keyword`, line 1 column 1 | 2 |
| `badchar` | `@print("not a letter")` | `unexpected character`, line 1 column 1 | 1 |
| `badesc` | `print("bad \q escape")` | `unsupported escape sequence, only \" and \\ are allowed`, line 1 column 7 | 2 |
| `trailing` | `print("one") print("two")` | `unexpected text after the closing parenthesis`, line 1 column 12 | 2 |
| `second` | a good statement, then `oops;` | `expected the print keyword`, **line 2** column 1 | 2 |

Every syntax case also prints the offending line and a caret under the token the
lexer was looking at, which is what the column numbers above point to. `second`
exists to show that line tracking survives a completed statement, and `badchar`
shows the one case whose exit code is 1 rather than 2: a character that cannot
start a token is a lexical fault, a malformed statement is a grammatical one.

## Command line and buffer cases

| Case | Invocation | Report | Exit |
| --- | --- | --- | --- |
| `usage` | no argument at all | `TinyPrint16 needs a source file.` and the usage line | 3 |
| `missing` | a file that does not exist | `cannot open source file`, `dos error 0002` | 3 |
| `overflow_source` | 300 statements, 6300 bytes | `source file is larger than the source buffer` | 3 |
| `overflow_thread` | 341 statements of `print("")` | `program is larger than the threaded-code buffer` | 3 |

The two overflow fixtures are generated by the harness into `build/` and deleted
afterwards, because they are thousands of bytes of one repeated line. `big.py`
exceeds the 4096-byte source arena; `many.py` fits in it (3751 bytes) and is
rejected only by the 1023-cell limit of the threaded buffer, which is what proves
the two limits are independent.

## `expected/`

Nineteen files, one per case, produced by the interpreter itself under DOSBox-X
and reviewed line by line. They are captures, not hand-written wishes: if a change
to a message alters the output, the suite fails and the diff says so.
